# CI/CD 课程项目复盘

>[代码详见此网址](https://github.com/hyvonz/CL-CD)

## 研究目的

### 总体目标

本课题的总体目标是设计并实现一套结构清晰、可重复执行、具有基本质量门禁和环境隔离能力的容器化 CI/CD 流水线。流水线需要能够从 Git 仓库获取项目代码，自动检查运行环境，执行应用测试，构建 Docker 镜像，将镜像部署至测试环境，对测试环境进行接口验证，并在人工确认后部署至生产环境

该目标强调的不是单个工具能否运行，而是不同工具之间能否形成稳定的协作关系。最终成果应同时包含可运行的应用、自动化测试、容器构建配置、环境部署配置、流水线脚本、统一命令入口和必要的项目文档

### 拟解决的关键问题

其一，如何确保本地环境和 Jenkins 环境执行相同逻辑。为此，项目没有将所有命令直接写入 Jenkinsfile，而是将主要操作封装为 Shell 脚本，再由 Jenkinsfile 和 Makefile 分别调用

其二，如何确保代码通过测试后才能构建和部署。为此，流水线采用严格的阶段顺序，任何前置阶段失败都会阻止后续步骤继续执行

其三，如何避免测试环境与生产环境端口、容器和网络冲突。为此，项目分别使用 cicd-demo-test 和 cicd-demo-prod 容器，并映射到主机的 18080 和 28080 端口，同时分别创建测试网络和生产网络

其四，如何判断容器不仅处于运行状态，而且内部服务能够正常响应。为此，Compose 配置中加入容器健康检查，流水线中又通过 curl 请求 /health 接口执行外部冒烟测试

其五，如何避免服务刚启动时因初始化尚未完成而造成误判。冒烟测试脚本采用多次重试机制，在每次失败后等待一定时间，达到最大次数后才判定部署失败

其六，如何在自动化部署效率和生产发布安全之间取得平衡。项目在测试环境冒烟测试成功后设置 Jenkins 人工确认节点，只有得到确认后才执行生产环境部署

## 总体技术路线

本课题采用“应用层—测试层—容器层—环境编排层—流水线脚本层—持续集成平台层”的分层设计。应用层由 Flask Web 应用组成，负责提供首页、健康检查接口和版本接口；测试层使用 Pytest 和 Flask 测试客户端对应用行为进行验证；容器层通过 Dockerfile 构建统一镜像；环境编排层通过 Docker Compose 描述测试和生产两套运行环境；流水线脚本层使用 Shell 脚本封装具体操作；最上层由 Jenkins Pipeline 进行阶段编排、状态展示和人工审批

一次完整流程为：开发人员修改代码并提交至 Git 仓库；Jenkins 获取最新代码；准备阶段检查项目文件、Python、Docker、Docker Compose 和 curl；测试阶段安装依赖并运行 Pytest；测试通过后构建带有 Jenkins 构建编号的 Docker 镜像；随后使用测试环境 Compose 文件启动容器；冒烟测试通过主机端口访问健康检查接口；验证成功后进入人工确认；确认后使用同一镜像部署生产环境，并再次执行健康检查；无论流程成功或失败，最终均输出容器和镜像状态，便于分析

## 主要研究结果

1. 完成了具备环境感知能力的 Flask 应用
2. 建立了基础自动化测试体系
3. 建立了基础自动化测试体系
4. 实现了测试与生产环境的配置隔离
5. 实现了容器内外两级健康验证
6. 实现了完整的 Jenkins 阶段化流水线
7. 实现了流水线脚本的模块化与复用
